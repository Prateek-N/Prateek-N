## ⚡ Featured Project

### 🧠 &nbsp;agents-maker &nbsp;·&nbsp; The Multi-Agent Stack

**_"Drop it in. Detect the domain. Route to the right specialist. Always know what's next."_**

<a href="https://multi-agent-stack.vercel.app/"><img src="https://img.shields.io/badge/Live%20Site-6366F1?style=for-the-badge&logo=vercel&logoColor=white" alt="Live site" /></a>

An open-source framework for dropping a **team of specialised AI agents** into any project. It reads the task,
detects the domain, and routes the work to the agent that should actually be doing it — so you stop
re-explaining your project to a fresh chat window every morning.

|  | What it does |
|:--|:--|
| 🎯 **Domain auto-detection** | Parses the task, identifies the domain, delegates to the right specialist — no more generic output |
| 🔁 **6-phase lifecycle** | Task Framing → Requirements → Solution Design → Implementation → Review → Handoff, with an approval gate at every seam |
| 🔌 **Provider-neutral** | One command generates native configs for **Claude Code, GitHub Copilot, Cursor & Antigravity** |
| 👥 **10 named agents** | Brain, PlanPro, Architect, Code, Execution, UI/UX, Reviewer, Compression — each with a real job |
| 🧩 **12 reusable skills** | Repo analysis, API design, code review, testing, process mapping — activated by context |
| 💾 **Cross-session memory** | Project state is committed as plain Markdown + YAML. Resume without replaying history |

```bash
# scaffold the kit into your project
npx @prateek_ai/agents-maker init

# ask it for a plan
python agents-maker/tools/generate_prompt.py "add rate limiting to the payments API"
```

> **Why it's built this way:** context quality over runtime automation. `agents-maker` structures the prompt
> instead of hijacking execution — which is exactly why it runs on any LLM, in any IDE, with `PyYAML` as its
> only dependency.
